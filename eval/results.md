# 골 감지 실측 결과

작성일: 2026-10-30  
검증 대상: 사용 가능한 영상 5편. 원래 전달된 영상 11개 중 사용 가능한 영상 5개를 선정함.

## 실험 조건

- 장비: MacBook Air M2, MPS GPU.
- 모델: `ball_s.pt`, 이미지 입력 크기 960.
- 영상별 골문 영역을 각각 지정함.
- 프레임별 공 검출 결과를 `detect_dump.py`로 저장하고, 이를 `tune.py`에서 판정 규칙에 적용해 평가함. 프레임 전체를 대상으로 한 사전 분석이며, 원래 영상 속도로 처리한 실시간 성능은 아님.
- 공통 판정 설정: `--conf 0.6 --min-in 0.03 --gap 0.2 --rearm 3 --cooldown 3`. 공 크기 제한 미적용.
- 각 영상의 실제 골 시각을 사람이 초 단위로 입력하고, 감지 시각이 해당 시각 ±2초 이내이면 골을 감지한 것으로 집계함. 시각이 대략적이므로 근접한 장면은 영상 대조 필요.
- 설정은 `test1`의 결과를 보면서 선택함. 따라서 test1 결과는 설정 선택에 사용된 결과이며 독립적인 검증 성능이 아님. 나머지 영상 결과도 영상 촬영 조건에 한정됨.

## 전체 영상 실행: 실제 골과 감지 시각 비교

`run.py` 이벤트 CSV를 사용했다. test3을 제외한 실제 골 시각은 사용자가 초 단위로 입력한 대략적인 시각이며, ±2초 이내 이벤트를 1:1로 대응한 예비 결과다. 영상에서 직접 확인하기 전에는 정확한 지연이나 누락 원인을 단정할 수 없다. 신호 시각은 영상 시간축이며 실제 처리 및 음성 출력 지연과 다르다.

- **test1:** 약 13→12.30초, 28→27.17초, 51→50.60초, 90→89.84초, 103→102.64초, 193→191.81초. 누락 후보 없음. 오탐 124.17, 165.98, 175.31초. 설정 선정에 사용된 영상이다.
- **test2:** 약 26→26.27초, 45→44.28초, 65→64.59초, 106→감지 없음, 115→115.00초, 155→155.38초, 242→240.84초. 누락 후보 약 106초(원인 미확인). 오탐 81.02, 188.32, 222.60, 253.08초.
- **test3:** 실제 13.47→13.47초, 42.70→감지 없음. 42.70초 햇빛 반사 상황 누락. 오탐 51.78초.
- **test4:** 약 13→12.24초, 30→28.98초, 55→54.75초, 67→67.15초, 78→77.56초, 89→감지 없음, 93→감지 없음, 97→감지 없음, 100→감지 없음, 113→112.43초. 누락 후보 약 89, 93, 97, 100초(원인 미확인). 오탐 후보 없음.
- **test5:** 약 12→11.74초, 28→26.71초, 38→37.71초, 58→57.48초, 74→74.86초, 96→94.43초, 108→감지 없음. 누락 후보 약 108초(원인 미확인). 오탐 86.83초.

## 실제 골 기준 시각 및 확인 내용

- **test1:** 13, 28, 51, 90, 103, 193초. 오탐 후보 3건은 골대 옆으로 공이 지나가며 이미지상의 골문 영역과 겹친 것으로 확인. 최초 `conf 0.35` 실행은 정탐 6, 오탐 후보 6건이었음. `conf 0.6`은 사전 분석 비교 결과이며 전체 실행 재검증 필요.
- **test2:** 26, 45, 65, 106, 115, 155, 242초. 처음 152초로 입력했으나 영상 확인 후 약 155초로 수정. 155.4초 판정은 수정된 실제 골과 대응됨. 사용자 확인 오탐: 81.0초 공이 그물 뒤로 감; 188.3초 공이 그물 밖에서 들어옴; 222.6초 공을 튀긴 장면; 253.1초 공을 들고 골대 앞을 지나간 장면. 155초는 실제 골로 유지한다.
- **test3 (152454):** 사용자 확인상 학습에 쓰지 않은 평가 영상. 실제 골 13.47초(골라인을 넘은 시점) → 감지 13.47초(conf 0.784), 영상 시각 차 0.00초(표시 정밀도 기준). 실제 골 42.70초는 누락: 팀원 확인상 햇빛 반사로 공이 하얗게 보이며 검출이 끊김. 51.78초(conf 0.742)는 사람이 공을 몰고 나올 때 오탐. `run.py --no-realtime --no-show`로 1,992프레임 전체 처리, 건너뜀 0, MPS, imgsz 960. 이벤트 CSV: `eval/results/test3_events.csv`. 영상 시각 차는 실제 처리 시간이나 스피커 출력 지연이 아님.
- **test4:** 13, 30, 55, 67, 78, 89, 93, 97, 100, 113초. 89~100초의 골 간격이 짧아 대기 또는 재준비 조건이 영향을 줬을 가능성이 있으나 원인 미확인. 영상 메타데이터상 3,701프레임, 저장 3,700프레임으로 1프레임 차이 있음.
- **test5:** 12, 28, 38, 58, 74, 96, 108초. 86.8초 오탐은 사용자가 골대 옆으로 공을 들고 나오는 장면이라고 확인함. 진단상 108초 ±1.5초 내 conf 0.25 이상 검출은 골문 영역 밖이었으나, 이것만으로 누락 원인을 확정할 수 없음.

## 누락 장면 확인 및 원인 분석

- **test2 약 106초:** 사람이 공을 손으로 던져 골문에 넣은 장면인데 골 이벤트가 기록되지 않았다. 밝기가 심하게 높지는 않았다고 사용자 확인. 공 검출 신뢰도, 골문 영역 내 위치, 판정 상태 등을 추가 확인해야 하며 햇빛을 원인으로 확정할 근거는 없다.
- **test3 42.70초:** 팀원 확인상 햇빛 반사로 공이 하얗게 보이고 검출이 끊긴 상황에서 놓쳤다.
- **test4 약 89·93·97·100초:** 사용자 확인상 공이 골대 바로 앞에서 반복적으로 드리블되는 상황. 공이 골문 안팎을 오가는 동안 감지기의 재준비(`rearm 3초`) 또는 대기(`cooldown 3초`) 상태가 영향을 미쳤을 가능성이 있으나 상태 로그를 확인해야 한다. 별도 백엔드에는 같은 골대 10초 제한이 있으나, 이번 이벤트 CSV는 서버 전송 없이 생성되었으므로 백엔드 제한을 이 이벤트 누락의 원인으로 단정할 수 없다.
- **test5 약 108초:** 사용자는 공이 빠르게 들어온 장면으로 보았다고 설명했다. 기존 진단에서는 해당 시각 ±1.5초에 신뢰도 0.25 이상 공 검출이 있었으나 골문 다각형 밖으로 표시됐다. 빠른 이동이나 골문 영역 지정이 영향을 줬을 가능성은 있으나 실제 원인은 추가 확인이 필요하다.

## 연동과 속도: 별도 시험

- 감지기 → 백엔드 → 점수판 및 해설 연동을 별도 Windows 영상에서 확인함.
- Windows `test_1.mp4`는 위 Mac `test1.mp4`와 동일 영상인지 확인되지 않아 5편의 합계에 포함하지 않음.
- 해당 Windows 영상의 전체 프레임 분석: 실제 골 7개 중 4개 감지, 3개 누락, 오탐 3개. CPU 약 5.6fps.
- 해당 Windows 영상의 원래 속도 분석: 실제 골 7개 중 1개 감지, 6개 누락, 오탐 2개. 3,525프레임 중 2,926프레임 건너뜀.
- 사전 분석 결과 재생 시 신호 7건 중 6건이 점수판에 반영됨. 17.14초 신호는 11.84초 신호 이후 백엔드의 같은 골대 10초 제한에 걸림.
- Mac `detect_dump.py` 별도 실행 마지막 표시 평균: test1 약 24.9fps, test2 약 23.7fps, test3 약 25.4fps, test4 약 26.1fps. 이는 검출 결과 저장 속도이며 시연 환경의 `run.py` 실시간 감지 성능이나 해설 지연과 같지 않음.

## 최종 평가에 필요한 작업
